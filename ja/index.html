WEBMCP · 読み取り専用4ツール · 完全な架空データ

ブラウザAIが、ページを読むだけでなく機器候補を構造化して調査する。

機器選定とは、書式の異なる仕様、基準の異なる価格、そして根拠に見えて根拠ではない 発見シグナルを突き合わせる作業です。ページを読むことしかできないAIが最初に誤るのが、 この突き合わせです。

そこで本ページは、その突き合わせ自体を4つの型付き関数としてブラウザのWebMCP APIへ 登録します。ページ内チャットボットではありません。

検討条件

それ自体では決着しない選定

96ウェルのqPCR装置を、6色マルチプレックス・GLP監査証跡あり・ 予算600万円以内で選定する。候補は架空レコード2件。数値はすべてデモ用の 架空値ですが、そこで生じる対立は、この仕組みが可視化しようとしている対立そのものです。

4条件をすべて満たす候補はありません。Bは機能条件を満たし、Aだけが架空の予算上限に収まります。

  • 96ウェル両方が該当
  • 6色マルチプレックスBのみ
  • GLP監査証跡Bのみ
  • 600万円以内Aのみ

構造化されたエージェントの調査フロー

1つの候補比較を、4回の確認可能な呼び出しで実行

順に実行し、各結果の上に出る平易な読み取りを確認してください。下のボタンは同じ検証済み 契約とハンドラーをローカル実行します。ブラウザAIがNative WebMCP経由で実行した 呼び出しだけが、下部のNative証跡へ記録されます。

01 · 検索

search_devices

8件の対象限定合成レコードを、テキスト、カテゴリ、作成者ラベル、状態から検索します。

{ "query": "RD-SYN qPCR", "limit": 2 }
02 · 正規化

compare_devices

同一カテゴリの値を宣言済みスキーマへ整列し、欠損値と製品順を保持します。

{ "productIds": ["rd-syn-qpcr-a", "rd-syn-qpcr-b"] }
03 · 価格コンテキスト

get_price_range

架空の通貨・価格basis・構成を分離し、存在しないレンジを推測しません。

{ "productIds": ["…a", "…b"], "currency": "JPY" }
04 · メソッドシグナル

get_literature_signal

応募者が作成した12件の架空レコード内の言及を、明確な意味づけとともに数えます。

{ "productIds": ["rd-syn-qpcr-a", "rd-syn-qpcr-b"] }

ページを読んだ場合

限定条件はすべて公開されています。ただし文章として、レコードページ・価格シナリオ ページ・メソッドコーパスに分散し、しかも2言語で書かれています。690万円を正しく扱うには、 AIは「単一観測はレンジではない」という注記を見つけ、それがその数値に適用されAの2件には 適用されないと判断し、さらに「No / なし」という語を真偽値へ変換しなければなりません。 どの段階も、静かに失敗しうる推測です。

結果：限定条件が値と別に流通し、脱落しても誰も報告しない。

get_price_range と compare_devices を呼んだ場合

限定条件が値に固定されて届きます。basis、configuration、 導出元の観測リスト、そして rangeStatus: "single_observation"。 690万円が自分の限界を自ら申告します。監査証跡は解釈が必要な語ではなく、 型付きの false として返ります。

結果：不確実性が、受け渡しの過程で失われない。
